# 电动滑板 ESP32-S3 控制系统提示词

你将扮演一位资深嵌入式开发工程师，需要基于 ESP32-S3 平台及 ESP-IDF 框架，为电动滑板项目编写完整、模块化的系统代码。请按照以下要求进行思考并输出最终的项目结构与示例代码片段以及必要的文档说明：

## 项目需求

1. **核心功能**：

   - 通过两个 HX711 传感器采集前后脚踩压力数据，并计算重心变化,计算需要的加速度,进而控制滑板前进/后退
   - 使用 can 读取倾角传感器检测坡度，并对电机动力进行自动补偿
   - 通过 UART 实时监测电池状态
   - 使用 NFC 读取/写入数据
   - 使用 GPS 获取位置信息（可根据需求做简化或增强）

2. **项目目录结构：**

   - 首先思考并给出一个合理且可扩展的目录结构，要求：
   - 在根目录（例如 “src/skateboard_foc_project”）下，按功能模块拆分各子目录
   - 每个模块都有独立的源代码、头文件、配置文件，并拥有单元测试文件
   - 能够方便地启用/禁用对应功能模块，便于调试和管理

3. **模块化设计：**

   - 具体的功能模块可能包括（示例）：
   - `motor_control_foc`：电机 FOC 控制逻辑、前后转向控制
   - `sensors`：包含 HX711、倾角传感器、NFC、GPS、其它传感器等
   - `communication`：CAN、UART、I2C 等通信相关逻辑
   - `battery_management`：对接电池状态监测和保护逻辑
   - `main_app`：主程序入口，完成初始化、任务调度、数据处理等
   - `utils`：常用工具函数，如数学运算、日志输出等

4. **单元测试与调试逻辑：**

   - 为各模块添加单元测试，例如使用 Unity 或 Catch2（ESP-IDF 兼容的测试框架），并能通过配置宏或 CMakeLists.txt 轻松开启/关闭单元测试
   - 提供示例单元测试用例，演示如何检查 HX711 读数、倾角传感器输出、FOC 算法核心逻辑等
   - 确保测试代码与业务逻辑分离，方便单独编译和测试

5. **ESP-IDF 及硬件依赖注意事项：**

   - 确定使用 ESP32-S3 + ESP-IDF，注意列出相应的 `idf.py` 配置或 `CMakeLists.txt` 示例
   - 程序中需初始化必要的硬件外设，并在主循环或 RTOS 任务中持续监控各传感器数据
   - 可以根据需要说明如何在编译时选择目标板，如何在 `menuconfig` 中配置外设引脚等

   - 适当加入简要的配置文件示例（如 CMakeLists）与单元测试用例示例
   - 在答案中详细说明此工程如何编译、运行与测试

7. **注意事项：**
   - 你的输出应先“思考”该如何搭建此项目，并给出行之有效的设计与示例代码
   - 核心强调“模块化”和“可测试”，让每个功能模块都易于维护与调试
